v0.2.0 截圖 · v0.4.0 尚未重拍

開機第一眼就是交辦列。桌機顯示完整桌面，手機顯示輸入框、任務列與 Dock 的細部裁切。剛裝好的機器還沒有任務，任務列只有一行提示。

首次設定精靈的其中一步。登入既有帳號或貼上 API 金鑰都可以，一家都不設也能先略過，之後在管理後台補。

03 / 準備試用

v0.4.0 走到哪裡了？

這是 pre-GA 技術試用版。先在可重裝的測試環境探索；1.0.0 才是第一個 GA 版本。

已驗證
QEMU 整碟映像開到登入畫面，兩種安裝器 ISO 開到 live 環境。
仍待驗證
真實 x86-64 硬體、這版安裝器的整段安裝、v0.3 → v0.4 A/B 升級與需要 LLM 授權的完整任務。
升級前留意
v0.4.0 改用 rootless gateway；成功開機後不能退回 v0.3.0 或更早版本。

完整驗證紀錄與未完成項目

展開 / 收合
  • 0.4.0 屬於 bring-up 階段，1.0.0 才是第一個 GA 版本。介面、分割佈局與設定格式都還可能變動。
  • 目前所有驗證都在 QEMU 完成，尚未在真實 x86-64 硬體上開機過。真機目標 duduclaw-genericx86-64 這一版只建置、沒有開機。v0.4.0 發布前，QEMU 版的整碟映像在 QEMU 開到登入畫面（約 65 秒），兩種安裝器 ISO 開到 live 環境的自動登入（各約 125 秒）；安裝精靈這一版沒有跑，跑完整段安裝的紀錄仍停在 v0.1.0 與 2026-09-06 的開發版。桌面版的測試映像另外跑了兩輪 rootless 驗證，第二輪 36 項過 35 項；從 v0.3.0 經 A/B 更新升級、需要 LLM 憑證的任務沙箱／電腦操作／Discovery 完整流程與 Windows 虛擬機都還沒驗證。
  • v0.4.0 起 gateway 不再以 root 執行，升級是單向的。gateway 改用一般帳號 duduclaw，桌面版的容器改用 rootless Podman。裝置成功開過 v0.4.0 之後就回不去 v0.3.0 或更早的版本；SSH 預設關閉，目前也沒有能透過 SSH 登入的帳號。
  • 發布映像沒有啟用 Secure Boot 簽章、dm-verity 與 TPM。相關 layer 已經接好，由建置 overlay 開啟；用官方映像開機前請在韌體裡關閉 Secure Boot。
  • 共駕功能已經編譯進映像，但預設關閉，每個 agent 要各自開啟。凍結、交還、急停與影子工作區在開發階段驗證過：容器裡用模擬輸入，QEMU 虛擬機裡用真實鍵盤滑鼠事件，那台虛擬機跑的是早期 arm64 開發映像，不是這版 x86-64 發布映像。真實 DRM 硬體與雙螢幕還沒驗。
  • v0.3.0 與更早的版本仍留在 Releases，資產與驗簽方式相同；開過 v0.4.0 的裝置不能經 A/B 更新退回這些版本。版本之間經 A/B 更新升級，目前沒有驗證紀錄。

硬體目標與建議規格
硬體

我的機器能跑嗎

以下是建置目標與規劃規格，不是真機相容認證。只提供 x86-64（x86-64-v3）映像；目前尚無真機開機數據。

x86-64 CPU 且支援 AVX2

Intel Haswell（2013 年）以後、Intel N100 / N200 / N305、AMD Excavator（2015 年）以後與 Zen 全系都符合。

不支援 arm64

Apple Silicon、樹莓派與 ARM 迷你主機都不能用。

UEFI 開機

純 legacy BIOS 的機器不在支援範圍。v0.4.0 的開機鏈未啟用 Secure Boot 簽章，開機前要在韌體裡關閉 Secure Boot。

SSD

A/B 雙槽佈局會同時放兩份系統，機械硬碟的隨機讀寫撐不住日常使用。

三種配置的建議規格

建議Intel N100 / N305 或 Ryzen 58 GB128 GB SSD
舒適（遊戲、本機 LLM）Ryzen 7 8845HS16 GB 以上256 GB SSD 以上

不需要獨立顯示卡；QEMU 上的桌面走 llvmpipe 軟體渲染，真機的 GPU 加速還沒驗證。以上規格都還沒有真機開機數據支撐。

資料存在哪裡，保護到哪一層

OS 的設定、AI CLI 憑證與模型存於本機 /data/duduclaw。使用雲端模型時，交辦內容與執行所需資料仍可能傳給供應商，依你選擇的工具與服務政策處理。

出貨即有

  • A/B 原子更新與回滾更新寫進另一槽；開機計數已接上；先前的映像實測過套用與手動回滾，v0.4.0 的升級路徑還沒驗證。
  • 唯讀 root（桌面版）系統分割區掛成唯讀，資料寫在獨立的 /data。
  • 發布產物 minisign 簽章六個資產同一把公鑰，燒錄前可以自己驗。

已接好但 v0.4.0 未啟用

  • Secure Boot 自簽與雙簽 UKI由建置 overlay 啟用；官方映像的開機鏈未啟用 Secure Boot 簽章，開機需關閉 Secure Boot。

  • TPM2 加 LUKS 磁碟金鑰部分完成，屬於建置 overlay 選項。

常見問題

試用前，你可能想知道

DuDuClaw OS 與 DuDuClaw 有什麼差別？

DuDuClaw 是 AI 員工平台，可部署在既有系統；DuDuClaw OS 是內嵌平台的 Linux 映像，加上交辦桌面、視窗系統與 A/B 更新鏈。OS 版號獨立，v0.4.0 內嵌平台 1.73.4，並非平台最新版本的全部功能。

現在適合取代日常主力機嗎？

目前建議用可重裝的測試環境試用。v0.4.0 是 pre-GA，驗證以 QEMU 為主，真機尚未開機；安裝器整段流程、真機 GPU 與雙螢幕仍未驗證。請先看目前狀態。

需要什麼硬體？Apple Silicon 可以嗎？

目標為支援 AVX2 的 x86-64 CPU、UEFI 與 SSD；規劃最低為 4 GB RAM、64 GB SSD，但尚無真機數據支持。arm64／Apple Silicon 不在支援範圍。官方映像開機需關閉 Secure Boot，詳見硬體條件。

需要另外準備 AI 帳號嗎？一定要連網嗎？

雲端 CLI 需要你自己的供應商帳號或 API 金鑰，費用與使用條款依供應商而定，不包含在 OS 下載中。桌面版可另行下載本機模型供離線推理；模型下載、雲端服務與網路任務仍需要連線，基礎版不含 AI CLI 與本機推理服務。

本機資料會傳到雲端嗎？

OS 設定、憑證與本機模型保存在本機資料分割區；但交辦給雲端模型時，提示、檔案內容與工具結果等執行所需資料可能傳給該供應商。資料去向由你配置的服務與工具決定；不能將本機部署理解成所有資料都不會出機。

可以用在商務環境嗎？

OS 開源程式碼採 Apache-2.0，內附元件仍各有授權。DuDuClaw 的企業導入、培訓與支援由總經銷 未來企業股份有限公司提供。OS 目前仍為 pre-GA，企業平台服務不代表 OS 已通過生產環境驗收。
